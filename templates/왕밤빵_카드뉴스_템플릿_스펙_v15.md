# 왕밤빵의 미국주식 베이커리 · 카드뉴스 템플릿 스펙 v15

이 문서 + 아래 에셋을 Claude에게 주고 "이 스펙대로 카드뉴스 만들어줘"라고 하면
동일한 디자인이 재현된다. v13/v14의 누적 규율을 하나로 정리한 통합본이다.

---

## 0. v15 정리 요약

v14까지의 규율을 통합하고, 실제 제작에서 확인된 결함 4건을 QA 자동 검출로 승격했다.

| 구분 | 핵심 |
|---|---|
| 정보량 | 카드당 콘텐츠 블록 **최대 3개**. 그래프 + 숫자 + 핵심문구만 남긴다 |
| 제목 | 본문 카드 제목은 **1줄**(리아산스 62px, 공백 포함 15자 내외) |
| 하단 결론 | **1줄 + 중앙 정렬**. 좌측 정렬 2줄 금지 |
| 여백 | 콘텐츠 하단 패딩 150px, 결론↔밴드 ≥60px, 마지막 블록↔결론 ≥45px |
| 캐릭터 배지 | 본문 168px 고정, 얼굴 중심이 원 중심에 오도록 정렬 |
| 결론 라벨 | **'왕밤빵의 한입요약'** (구 '밤슐랭 투자레시피'에서 변경) |
| QA | 기존 6단계 + 2b·2c·2d·2e 신설 = 총 10개 검사, 전 카드 PASS까지 반복 |

**v15에서 QA로 승격된 결함 4건**

1. 하단 결론 박스가 골드 밴드에 붙어 답답함 → `2b/하단숨통`
2. 마지막 콘텐츠 블록이 결론 박스에 붙음 → `2c/블록간격`
3. 가로 바 차트의 수치 텍스트가 우측 여백(72px)을 뚫고 나감 → `2d/좌우여백`
4. 고정폭 라벨의 긴 종목명이 옆 바 위로 삐져나감 → `2e/박스이탈`

## 3. 레이아웃 규칙 (모든 카드 공통)

1. **최외곽 프레임** — 캔버스 전체에 6px 골드 직사각 프레임 (`body::after`, z-index 최상위)

   12px 라운드, `5px 5px 0` 브라운 하드섀도. 페이지 번호는 표기하지 않음.
   표지만 좌측 "WBB REPORT" + 대시 + 우측 태그칩 구성.
3. **제목 h1** — 리아산스 62px(표지 88px), line-height 1.22, `white-space:nowrap`,
   `padding-right:180px`(배지 클리어런스). 핵심 키워드만 `.o` 오렌지.
4. **콘텐츠 박스** — 흰 배경, 3.5px 브라운 테두리, 18px 라운드,
   `7px 7px 0 rgba(59,35,20,.14)` 소프트 하드섀도
5. **푸터** — 골드 밴드 풀블리드, 높이 76px, 상단 4px 브라운 실선,
   좌측 태그라인 "어려운 미국주식, 한입에 이해되게"(800 / 26px), 우측 로고(높이 42px).
   출처는 카드에 표기하지 않음(블로그 본문에서 처리).
6. **결론 박스** — `margin-top:auto`로 하단에 고정. 카드 중앙에 붕 띄우지 않는다.

## 4. 정보량 · 크기 위계 규율

### 정보량 상한
- 본문 카드 기본형 = **제목 + 주 시각요소 1개 + 하단 1줄 결론**
- 콘텐츠 블록은 **최대 3개**. 설명문·부연·괄호주석·조건부 단서는 블로그 본문으로.
- 카드는 "한눈에 와닿는 그림"이 목적. 표로 정리할 내용은 어차피 본문에서 다룬다.

### 제목
- 본문 카드 제목은 **1줄**. 2줄 금지 — 안 들어가면 문장을 줄인다.
- 카드의 핵심 내용을 직관적으로 전달. **베이커리 말장난 제목 금지.**
- 예: "단일 티커가 없다 / 플랫폼마다 입력값이 다르다" → **"플랫폼마다 티커가 다르다"**

### 하단 결론
- 한 문장 **1줄**, `text-align:center`. 좌측 정렬 2줄 스트립은 시선이 쏠려 답답하다.

### 크기 위계
| 요소 | 크기 |
|---|---|
| 핵심 수치 (hero) | 리아산스 58~96px |
| 항목 제목 / 종목명 | 800, 32~44px |
| 3분할 박스 주 텍스트 | 리아산스 **34~38px 상한** (좌우 패딩 최소 18px) |
| 번호 리스트 번호 | 리아산스 58px |
| 결론 박스 핵심문구 | 리아산스 38~44px |
| 보조 설명 | 500, 22~26px |
| 축 라벨 · 캡션 | **22~24px** (본문급으로 키우지 않는다) |

모든 요소가 비슷한 크기가 되는 것을 금지한다.

## 5. 여백 규율

| 구간 | 기준 |
|---|---|
| 제목 아래 → 첫 콘텐츠 | **최소 70px** |
| 콘텐츠 블록 사이 | **최소 40px** |
| 마지막 블록 → 하단 결론 박스 | **최소 45px** (QA 2c) |
| 하단 결론 박스 → 골드 밴드 | **최소 60px** (QA 2b, 콘텐츠 패딩 150px로 확보) |
| 요소 사이에 끼는 라벨(브레이스 캡션 등) → 위쪽 요소 | **최소 35px** |

**대칭 수직 센터링 금지.** 남는 여백은 센터링으로 얼버무리지 말고
셀 패딩 · 바 높이 · 박스 패딩 · 리스트 항목 간격을 키워 흡수한다.

> **실무 팁** — 여백 조정은 눈으로 하지 말고 측정한다.
> `블록→결론`, `결론→밴드` 갭을 출력하는 스크립트(gap.py)를 돌려
> 목표치(50~70px)에 맞을 때까지 패딩을 가감하는 편이 반복 횟수가 적다.

## 6. 줄바꿈 규율

- **자동 줄바꿈에 맡기지 않는다.** 모든 텍스트는 `white-space:nowrap` + 수동 `<br>`.
- 1줄이 기본. 안 들어가면 먼저 문장을 줄인다(조사·수식어 삭제).
- 2줄이 필요하면 **의미 단위로 끊는다** — 주어부/서술부, 사건/출처, 원인/결과 경계.
- 렌더 후 QA에서 라인박스 개수 > (`<br>` 개수 + 1 + 블록 자식 개수)면 실패.

## 7. 강조 규율

- 긍정 수치·개선: 초록 음영 `.hl-pos` (배경 `#DFEFD3` / 글자 `#2E6420` 800)
- 부정 수치·리스크: 빨강 음영 `.hl-neg` (배경 `#F9DCDC` / 글자 `#B02E2E` 800)
- 일반 강조: 갈색 굵게 `.st` (`#3B2314`, 800)
- 오렌지 `.o`는 **제목과 하단 결론 문구에만**.
  CSS는 반드시 `h1 .o, .o { color:#BC4A0A }`로 **전역 선언**한다.
  `h1 .o`만 선언하면 결론 박스의 강조가 먹지 않는다 (실제 발생 사례).
- 골드 `#F5A41C`는 텍스트 강조에 쓰지 않고 구조 요소(칩·표 헤더·차트 바) 전용
- 한 박스에 음영 하이라이트는 최대 2개

## 8. 시각화 우선 원칙

**모든 본문 카드는 표 또는 차트를 '주인공'으로 구성한다. 표보다 그래프를 우선한다.**

### 차트 유형 가이드
| 값의 성격 | 형식 |
|---|---|
| 항목 간 크기 비교 | 가로 바 차트 |
| 구성비·비중 | 도넛 |
| Before → After | 화살표 표기 (`구값 ▶ 신값`, 신값에 음영) |
| 대비 구조 (A vs B) | 2열 비교 박스 |
| 시간 순 변화 | 3스텝 pill 타임라인 (마지막 스텝만 강조색) |
| 나열형 체크포인트 | 박스 없는 번호 리스트 (번호 리아산스 58px) |
| 대응 관계 정보 (그래프 전환 불가) | 표 — **최대 4행** |

### 가로 바 차트 규격
- 골드 바 + 3.5px 브라운 테두리. 하락/부정 항목만 레드.
- **바 요소는 `width:{n}px; flex:0 0 {n}px`로 축소 금지.**
  flex 컨테이너에서 shrink되면 서로 다른 값의 바가 같은 폭으로 렌더된다.
- **바 최대폭은 역산해서 정한다:**

  ```
  바 최대폭 = 936 − 라벨 고정폭 − gap − gap − 수치 텍스트 실측폭
  ```

  이 계산을 생략하면 수치 텍스트가 우측 여백을 뚫고 나간다 (QA 2d에서 검출).
  라벨이 긴 종목명("어플라이드 머티어리얼즈")이면 라벨 폭을 300px 이상으로 잡고
  바 폭을 다시 배분한다 (QA 2e).
- 렌더 후 픽셀/DOM 실측으로 (바1 폭 ÷ 바2 폭)이 (값1 ÷ 값2) 대비 ±3% 이내인지 검증.

### 도넛 규격
- 골드 호 + 피치 링 + 내·외곽 3.5px 브라운 테두리, `conic-gradient` 사용
- **홀 지름 ≥ 도넛 지름의 66%** — 중앙 수치가 링에 겹쳐 보이지 않게
  (예: 300px 도넛 → 홀 202px)
- 중앙에 리아산스 큰 수치(오렌지) + 페이퍼로지 보조 레이블

### 표 규격
- 헤더 골드 배경 800 / 27~30px, 셀 600 / 27~30px, 행머리는 크림 배경
- **최대 4행.** 5행 이상 필요하면 우선순위 낮은 행을 블로그 본문으로 내린다.
- 상태·결과 칼럼은 pill 배지 (초록/빨강/골드)

## 9. 캐릭터 배치

### 표지 — 원형 배지
- 피치색 원 **260px**, 브라운 4px 테두리 + `8px 8px 0` 하드섀도
- 캐릭터 높이 **232px**, `left:50%; top:49%; transform:translate(-50%,-50%)`
- 원 하단에 "경제왕밤빵" 스티커 이름표 (리아산스 31px, 오렌지 배경, 3px 테두리, 수평 정렬)
- 배지는 서브텍스트와 골드 밴드 사이 남는 공간의 수직 중앙에
  (`margin-top:auto; margin-bottom:auto`) — 표지에만 적용되는 예외

### 본문 카드 — 우측 상단 고정 배지
- 피치색 원 **168px**, 브라운 4px 테두리, 앵커 `top:44px; right:52px`
- 표정 이미지 `height:176px; left:50%; top:62%; transform:translate(-50%,-50%)`
  → **얼굴 중심이 원 중심에 오도록** (`top:50%`면 얼굴이 위로 쏠려 잘려 보인다)
- 카드마다 위치가 흔들리지 않게 고정 좌표 유지
- **배지는 제목·그래프·표·박스 어떤 것과도 겹치지 않는다.**
  겹치면 배지를 옮기지 말고 콘텐츠(주로 제목)를 축약한다.
- 카드당 캐릭터 1개. 별도 코멘트 박스 만들지 않음.

### 표정 매핑
| 상황 | 표정 |
|---|---|
| 어닝 서프라이즈 / 급등 | `surprise` |
| 호재 확인 / 자신감 | `confident` |
| 개념 설명 / 가이드 | `knead` |
| 의문 제기 | `question` |
| 고민 · 관전 포인트 · 신중한 결론 | `think` |
| 악재 · 가산세 · 리스크 | `panic` |
| 손실 · 막힘 | `cry` |
| 과열 · 질타 · 경고 | `angry` |
| 반전 코멘트 | `smug` |

## 10. 세트 구성

**원고(제목 + 소제목)만 받아 `표지 1장 + 소제목별 1장`으로 구성한다.**
'핵심 요약'과 'Q&A' 섹션은 카드로 출력하지 않는다.
→ 소제목 3개면 4장, 4개면 5장.

- **표지** — 태그칩(경제 이슈 / 정책 이슈 / 증시 이슈 / 지정학 이슈 / 생활 경제 등),
  제목은 글의 핵심 질문·대비 구조로 재구성, 서브텍스트 1줄, 원형 배지 캐릭터
- **본문 카드** — 소제목 1개당 1장. 소제목을 그대로 쓰지 말고 카드 제목 규율(1줄·직관적)에 맞춰 재작성
- **마지막 카드** — 결론 역할. 하단에 **'왕밤빵의 한입요약'** 박스
  (오렌지 라벨 pill + 리아산스 38~44px 핵심문구 1줄)

### 콘텐츠 원칙
- 한 카드 = 한 메시지
- **수치·기업명·날짜는 원고에 있는 것만.** 임의 계산·추정 금지.
- 시점 고정 표현("이미 지났다", "아직 안 늦었다", "경과/진행 중") 주의 —
  원고가 상시(evergreen)형이면 카드도 상시형으로. 상태 배지는 시점 고정 표현이 되기 쉽다.
- 정치·갈등 사안은 좌우 동일 크기·동일 구조로 배치하고 발언 주체에 귀속시킨다.
  결론은 양측이 합의하는 지점으로 맺는다.

## 11. 제작 파이프라인

```
HTML/CSS 작성 → Playwright(Chromium) 1080×1080 뷰포트, DSF 2배 스크린샷
             → PIL LANCZOS 다운스케일 1080px PNG
             → render_qa.py 전 카드 PASS까지 반복
             → 모든 PNG를 실제로 열어 육안 검수
```

### 샌드박스 환경 구성 (네트워크 차단 우회)
- **폰트**: 사용자 업로드분을 `~/.fonts`에 복사 후 `fc-cache -f`.
  CSS는 `@font-face { src: url('file:///.../파일명.otf') }`로 직접 참조.
- **Chromium**: `cdn.playwright.dev`가 차단되므로 npm 레지스트리 경유로 우회.
  ```
  curl -L https://registry.npmjs.org/@sparticuz/chromium/-/chromium-149.0.0.tgz
  → tar 해제 → bin/chromium.br 을 brotli 해제 → chmod +x
  → swiftshader.tar / al2023.tar 도 해제
  → playwright launch(executable_path=...) 로 지정
  ```
- **/tmp는 세션 중에도 초기화된다.** Chromium은 `~/chrbin`처럼 홈 아래에 두어야
  세션 중간에 사라지지 않는다. (`~/.fonts`는 유지됨)

### 산출물
- 카드별 PNG, 파일명 `01_표지.png`, `02_○○.png` … 정렬 순서 = 게시 순서
- **파일명에 '무슨', '쟁점', '서프라이즈' 같은 음절 조합은 경로 전달 중 글자가 깨진다.**
  짧고 단순한 음절로 짓는다 (`02_고발`, `04_논점`).

## 13. 알려진 실패 모드

**렌더링·레이아웃**
- `flex:0 0 {n}px` 누락 시 바가 shrink되어 서로 다른 값이 등폭으로 렌더됨
- 바 최대폭 역산 생략 시 수치 텍스트가 우측 여백을 뚫고 나감
- 고정폭 라벨에 긴 종목명 → 텍스트가 옆 바 위로 삐져나옴
- 콘텐츠가 flex 컨테이너를 넘치면 `margin-top:auto` 결론 박스가 패딩 밖으로 밀려남
  (캔버스 안이라 오버플로 검사에는 안 걸린다 → 2b/2c가 잡는다)
- `h1 .o`만 선언 시 결론 박스 오렌지 강조 미적용

**타이포그래피**
- 리아산스에서 숫자 `0`이 알파벳 `O`처럼 보임 → 단독 사용 피하고 문구로 대체
- 인라인 span의 폰트 크기가 다르면 줄바꿈 검사가 오탐 (중심 기준 클러스터링으로 해결)

**도구·환경**
- CSS 일괄 문자열 치환 시 변경이력·설명문까지 함께 치환되어 문서가 손상됨
  → 치환 대상을 좁히고 적용 후 결과를 확인할 것
- 한글 파일명 일부 음절이 경로 전달 과정에서 깨짐
- `str_replace` 무음 실패 (클래스명 불일치) — 적용 여부를 항상 확인
- CSS 속성 중복 선언 (뒤 선언이 이김)
